# Outline: The Metadatafication of Version Control

## Core Thesis
Git will not disappear, but it will undergo "metadatafication" — becoming invisible infrastructure that AI agents operate on behalf of developers, much like EXIF data, DNS, or TCP/IP. The developer community's focus will shift from examining code diffs to optimizing how context is fed to AI agents, and software distribution will migrate from app stores to capability marketplaces (MCP).

## 1. Introduction
- Git is 20+ years old (2005). In that same span: Yahoo → Google, Blockbuster → Netflix, CD → Streaming.
- Current discourse: "Is Git dying?" — wrong question.
- Right question: What does Git become when AI agents are the primary code authors?
- Thesis: Git undergoes metadatafication — records persist but direct human interaction fades.

## 3. The Metadatafication Thesis
### 3.1 Definition
- Metadatafication: the process by which a directly-operated tool becomes automatically-generated background data
- Not obsolescence — continued existence without direct interaction

### 3.2 Historical Precedents
| Technology | Active Tool Era | Metadatafied Era |
|---|---|---|
| EXIF | Manual photo parameter recording | Auto-embedded, rarely viewed |
| DNS | Direct IP address management | Transparent name resolution |
| TCP/IP | Manual network configuration | Invisible transport layer |
| File systems | DOS directory management | Abstracted away on smartphones |
| Compiler optimization | Hand-written assembly | Automatic, developer-invisible |

### 3.3 Git Function-by-Function Analysis
- `git commit` → auto-generated by agents (already happening: Claude Code, Copilot)
- `git branch` → agent sessions replace branching mental model
- `git diff` / code review → intent review replaces line-by-line review
- `git blame` → meaningless when AI authored the code
- `git merge` → agent-coordinated, no human conflict resolution
- `git log` → equivalent to server access logs: exists, rarely read

## 4. The Redistribution of Developer Attention
### 4.1 From Code Inspection to Context Engineering
- Line-by-line code review communities lose leverage
- New competency: how to feed context to agents effectively
- AGENTS.md, CLAUDE.md as new collaboration artifacts (arxiv:2601.20404)

### 4.2 From App Stores to Capability Marketplaces
- App store model: curated directory of packaged software (≈ Yahoo Directory)
- Ephemeral/JIT software: AI generates on demand (≈ Google Search)
- Template preference persists → addressed by capability composition
- MCP as "capability package manager":
  - npm/pip = code library catalog
  - MCP registry = capability catalog
  - AI composes capabilities instead of developer assembling libraries

### 4.3 The Four-Layer Framework
| Layer | Legacy Model | Emerging Model |
|---|---|---|
| Distribution | App stores | AI on-demand generation |
| Reuse | Templates / boilerplate | MCP servers (capability catalog) |
| Collaboration | GitHub PR / code review | Agent sessions / intent review |
| Version Control | Git (code diffs) | Spec versioning / auto-snapshots |

In all four layers, Git shifts from foreground tool to background infrastructure.

## 5. Implications
### 5.1 For Education
- Teaching Git mechanics becomes low-priority (like teaching assembly)
- New curriculum: prompt engineering, context management, spec writing, agent orchestration

### 5.2 For Tooling
- Agent-native VCS design principles (Atomic, Manyana)
- CI/CD triggers: commit push → agent session completion
- Review interfaces: spec diff, test result diff, intent diff

### 5.3 For Ecosystem Governance
- MCP registry governance parallels npm/PyPI governance challenges
- Trust, verification, capability composition safety
- Open questions: who audits AI-composed capability chains?

## 6. Counterarguments and Limitations
- LLM non-determinism: can't version prompts alone (RHSeeger, HN)
- Edge cases discovered only through deployment reset on regeneration (Kirsch, 2026)
- Critical systems still require formal verification
- "Malleable software" as middle ground (Kirsch, 2026)
- Network effects: Git's moat is ecosystem, not technology
- Metadatafication ≠ irrelevance: metadata can become critical in forensics, compliance

## 7. Conclusion
- Git is not dying. It is becoming invisible.
- The developer's relationship with version control follows the same trajectory as every infrastructure technology before it.
- The community that thrives will be the one that optimizes for agent-readability, not human-readability of code.
- The next GitHub is not a better Git forge — it is a capability marketplace.
